## Notes & Assumptions

_(working notes, [ASSUMPTION] tags, [NOTE FOR UX] items — triaged at Finalize)_

- **N1** Game pillars (mirror verbatim in copy): P1 Godhood — *"How overpowered can I become?"* · P2 The Gamble — *"How far will I push my greed?"* · P3 The Test — *"How far can skill carry it?"*. Run-phase mottos: build = *"How OP can I become"*, endless = *"how far can I push it"* — endless phase is named **"the Ascender phase."**
- **N2** Sequencing (from epics): **v0.1 (E1–E3)** first surfaces = basic HUD (HP/ships/wave/score), juice layer, captor telegraph, docked-ship + sacrifice-burst feedback, **power-up select (3-choose-1)**, **shop (4 offers)**, debug overlay. **v0.5 (E4)** = scene flow menu→run→gameover, basic pause, wave-lifecycle transitions. **v1.0 (E5–E8)** = full HUD polish, main menu, full pause, game-over, settings (volume + input remap), modifier readability, post-victory/endless/tier flow, feat/unlock notifications, godhood-peak juice. **Post-1.0 (E9)** = daily challenge, shareable seed codes, leaderboards.
- **N3** "Meridian" naming duality (line-through-poles 1-axis geometry + peak/ascent) — usable as menu/brand motif.
- **N4** Primary audience = roguelite build-crafters (Brotato/VS/Hades/Isaac) who want "juice, readability, clear power-up feedback, progression UI over shmup-purist minimalism."
- **N5 — Player journey anchor: Rosa (wave-20 climax).** Named protagonist for the Key Flows section. *One ship left at wave 20 → must NOT court capture (no life left to rescue with = game over). Screen approaches overwhelming. In that moment her attention: player-ship location + enemy fire-columns (to track enemy positions); occasional HUD glance; a full HUD read only in the death→respawn window.* Drives H4 (on-ship HP is the one always-attended read), S1 (focus/fade; surface in calm moments), and the readability caveat on C1/C2 ("power = bigger + glowier" must still let Rosa parse her true hitbox at the peak).
- **N6 — Color meaning is screen-scoped.** The same hue may carry different meanings on different screens as long as those screens never co-occur (e.g. generator-green on a build card vs HP-green in the in-wave HUD — no conflict, because build screens overlay a paused arena, never the live HUD). Justifies keeping family colors on existing tokens (I1) without conflation risk. Candidate for DESIGN.md Do's & Don'ts.
